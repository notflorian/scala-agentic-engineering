# 13. Minimale Review-Unterlagen für weniger Rückfragen

Bevor Sie eine Review bei Codex anfordern, bereitet Claude oder ein Kollege immer ein kurzes Paket vor:

```text
Ticket/spec :
Objectif :
Non-objectifs :
Fichiers modifiés :
Base SHA / merge base / PR head SHA :
Diff base → candidat + fichiers non suivis :
Exigences → preuves (commandes, résultats, rapports et SHA) :
Tests exécutés :
Tests non exécutés et pourquoi :
Risques résiduels :
Questions ouvertes :
```

Gibt nicht nur das diff. Eine Review ohne spec produziert allgemeine Kommentare; eine Review mit Ziel, Grenzen und Tests produziert häufiger agilable Rückmeldungen. Zuerst den Vertrag und den Diff ohne die Schlussfolgerungen des writer; die Begründungen kommen nach der ersten unabhängigen Analyse. Das Paket muss regeneriert werden, wenn das SHA ändert.

> können größer sein (408 Zeilen gegen 157 am 75e Perzentil.

Bei den Prs-Agenten ist besonders zu überwachen:

```text
- nombre de fichiers modifiés ;
- taille du diff ;
- fichiers hors scope ;
- CI rouge ;
- tests ajoutés qui ne peuvent pas échouer ;
- refactor non demandé ;
- changement implicite de contrat public ou JSON ;
- modification de build sans validation.
```
