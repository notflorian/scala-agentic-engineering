# 11. When to use Aider and where OpenCode and Qwen Code fit

Aider remains useful, maintained and very effective for **pair programming terminal oriented Git**: it is given accurate files, it produces readable patches, and the history Git remains the undo stack.

OpenCode is a more generalist open source agent, with terminal, IDE/desktop depending on configuration, multiple sessions and LSP/ integrationsMCP. For Scala, it's interesting, but you have to stay precise: some LSP capabilities are still documented as experimental or dependent on a configuration flag, and **Metals is not part of the cabled LSPs natively** — the application for integration opened on the deposit OpenCode (January 2026) is still at the discussion stage in mid-July 2026. In practice, feedback compiler Scala reliable in OpenCode passes either through manual LSP config or through the **Metals MCP standalone** (section 9), which remains the recommended path. Therefore, does not base a team architecture decision only onOpenCode Test it on your repo, with Metals, then measures the quality of the diffs.

Qwen Code is now more than just a harness for Qwen : **Auto-Memory, Auto-Skills, Subagents, MCP, LSP, worktrees Git, headless mode and suppliers OpenAI/Anthropic/Qwen/local** make it a serious open source alternative to Claude Code and Codex. Versions **0.24.x** precisely reinforce the points that matter to this guide: `agent()` may receive a **explicitallowlist of tools**, workflows record checkspoints and can be re-taken or re-launched, subagents can be insulated in containers, and the context injected by files/extensions as well as the *tool surface* and limitable. **0.24.7**, the deferred tools may be **lazy-loaded in Mode Code** : `tools.eager` only retain the necessary schemas in the initial request, the others remain
recorded and discovered via `tool_search` → `tool_call`. The same release adds a **Structured reminder on request** and continues sustainable sessions/workspaces. This is a particularly clear implementation of `Select + Isolate` : removes unnecessary schemas from the prefix without losing the ability to call the tool later. The foundation of Linux sandbox now relies on `bwrap`. **Agent Teams** and **Agent Arena** Arena is particularly useful for the private benchmark, as several models can receive the same task in isolated worktrees. `/advisor` provides a second independent opinion. OpenCode Empirical remains: quality of patches Scalastability with Metals, total cost and quality of permission management. Local Control must remain

## When to use Aider

Use it to:

* small targeted patch;
* correction of a test;
* local renaming;
* simple mechanical migration;
* change where the diff Git is central;
* loop lint/test very short.

Do not use it for:

* architecture;
* big legacy;
* multi-module bugs;
* deep trade refactor;
* design decision.

Aider Is all the better if you respect this rule: **add few files, give a specific request, check the diff, run targeted tests**. If you add too many files, you recreate the problem you wanted to avoid: expensive context, diluted attention, wider diff.

If this discipline matters to you less than LSP feedback, OpenCode/Qwen Code can better cover the same cases, but only after local validation on your repo Scala.

## Example: the test command that any harness must receive

The number one lever of the lint/test loop is a common, reproducible and fast command. Do not deduct `FooSpec` from the name of `Foo.scala`: the suite can carry another name and a `testOnly` without a selected test can succeed. On a clean CI, `git diff HEAD` does not see the commits of the PR. So fix a **baseGit immutable** and compare it to the candidate (basemer), taking into account all the states Git for the local feedback.

Example `scripts/ai-validate.py` (Python 3, Git, sbt; adapt `MODULES`, path policy and JUnit reports to the project). The listed suites must cover all test modules, including integration modules; a non-test suite run requires an explicit configuration, not a silent success.

```python
#!/usr/bin/env python3
"""Repository-specific example: adapt and protect the module map and policy."""
import argparse
import json
import re
import subprocess
import sys
import xml.etree.ElementTree as ET
from pathlib import Path

MODULES = {"api/": "api", "integration/": "integration"}
PROTECTED_NAMES = {"build.sbt", "plugins.sbt", "AGENTS.md", "CLAUDE.md", "CODEOWNERS", ".gitmodules"}
PROTECTED_DIRS = {".github", ".claude", ".codex", ".agents", "project", "migrations", "scripts"}
MAX_FILES, MAX_LINES = 20, 600


def git(*args):
    return subprocess.check_output(["git", *args])


def nul_paths(*args):
    return {p.decode("utf-8", "surrogateescape") for p in git(*args).split(b"\0") if p}


def changed_paths(base):
    # Union of committed, staged, unstaged and untracked paths; count renames as delete/add.
    return (nul_paths("diff", "--name-only", "-z", "--no-renames", base, "HEAD")
            | nul_paths("diff", "--cached", "--name-only", "-z", "--no-renames", base)
            | nul_paths("diff", "--name-only", "-z", "--no-renames", base)
            | nul_paths("ls-files", "--others", "--exclude-standard", "-z"))


def protected(path):
    parts = Path(path).parts
    return (bool(set(parts) & PROTECTED_DIRS) or Path(path).name in PROTECTED_NAMES
            or path.endswith(".sbt"))


def check_diff(base, head):
    # A final proof requires a committed candidate; never ignore untracked files.
    if git("status", "--porcelain=v1", "-z", "--untracked-files=all"):
        raise ValueError("Dirty candidate (including untracked files); inspect and commit authorized files first")
    raw = git("diff", "--raw", "-z", "--no-renames", base, head).split(b"\0")
    for metadata, raw_path in zip(raw[0:-1:2], raw[1:-1:2]):
        old_mode, new_mode = metadata[1:].split(b" ", 2)[:2]
        if {old_mode, new_mode} & {b"120000", b"160000"}:
            raise ValueError(f"Symlink or submodule requires separate review: {raw_path!r}")
    records = git("diff", "--numstat", "-z", "--no-renames", base, head).split(b"\0")
    count, lines = 0, 0
    for record in filter(None, records):
        added, removed, raw_path = record.split(b"\t", 2)
        path = raw_path.decode("utf-8", "surrogateescape")
        if protected(path):
            raise ValueError(f"Protected path requires separate human-approved policy: {path!r}")
        if added == b"-" or removed == b"-":
            raise ValueError(f"Binary change requires separate review: {path!r}")
        count += 1
        lines += int(added) + int(removed)
    if count > MAX_FILES or lines > MAX_LINES:
        raise ValueError(f"Diff exceeds policy: {count} files, {lines} lines")
    return {"files": count, "lines": lines}


def select_modules(paths):
    # Unknown/shared changes or no identified tests -> all declared test modules.
    if not paths or any(not any(p.startswith(prefix) for prefix in MODULES) for p in paths):
        return list(MODULES.values())
    return [module for prefix, module in MODULES.items()
            if any(path.startswith(prefix) for path in paths)]


def run_step(args, results):
    rc = subprocess.run(args, check=False).returncode
    results.append({"argv": args, "exit_code": rc})
    if rc:
        raise ValueError(f"Command failed ({rc}): {args!r}")


def verify_reports(prefix):
    # Adapt to actual report paths and frameworks; after clean, no stale reports.
    executed = 0
    for report in Path(prefix).glob("target/**/TEST-*.xml"):
        suite = ET.parse(report).getroot()
        if suite.tag != "testsuite":
            raise ValueError(f"Unexpected report format: {report}")
        if int(suite.get("failures", "0")) or int(suite.get("errors", "0")):
            raise ValueError(f"Failed tests in report: {report}")
        executed += int(suite.attrib["tests"]) - int(suite.get("skipped", "0"))
    if executed <= 0:
        raise ValueError(f"No executed tests proven for {prefix}")
    return executed


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--base", required=True, help="Approved full Git commit SHA")
    parser.add_argument("--mode", choices=["targeted", "validate"], required=True)
    parser.add_argument("--sbt2", action="store_true")
    parser.add_argument("--receipt", type=Path, required=True)
    args = parser.parse_args()
    root = Path(git("rev-parse", "--show-toplevel").decode().strip()).resolve()
    receipt = args.receipt.resolve()
    if receipt == root or root in receipt.parents:
        parser.error("Receipt must be outside the repository")
    import os
    os.chdir(root)
    result = {"base": args.base, "mode": args.mode, "steps": [], "status": "FAILED"}
    try:
        if not re.fullmatch(r"[0-9a-f]{40}|[0-9a-f]{64}", args.base):
            raise ValueError("Expected a full immutable base SHA")
        head = git("rev-parse", "HEAD").decode().strip()
        base = git("merge-base", args.base, head).decode().strip()
        result.update(head=head, merge_base=base)
        if args.mode == "validate":
            result["diff"] = check_diff(base, head)
            modules = list(MODULES.values())
            # Full final validation, not a heuristic selection.
            run_step(["sbt", "scalafmtCheckAll", "compile", "Test/compile"], result["steps"])
        else:
            modules = select_modules(changed_paths(base))
        result["modules"] = modules
        test_task = "testFull" if args.sbt2 else "test"
        for prefix, module in MODULES.items():
            if module not in modules:
                continue
            # Explicit module suite: do not infer test names from source filenames.
            command = ["sbt", f"project {module}"]
            if args.mode == "validate":
                command.append("clean")
            run_step([*command, test_task], result["steps"])
            if args.mode == "validate":
                result.setdefault("executed_tests", {})[module] = verify_reports(prefix)
        if args.mode == "validate":
            if git("rev-parse", "HEAD").decode().strip() != head:
                raise ValueError("Candidate SHA changed during validation")
            check_diff(base, head)
            result["status"] = "PASSED"
        else:
            result["status"] = "FEEDBACK_ONLY"
    except (OSError, ValueError, subprocess.SubprocessError, ET.ParseError, KeyError) as exc:
        result["error"] = str(exc)
    finally:
        receipt.write_text(json.dumps(result, indent=2) + "\n", encoding="utf-8")
    print(json.dumps(result))
    return 0 if result["status"] in {"PASSED", "FEEDBACK_ONLY"} else 1


if __name__ == "__main__":
    sys.exit(main())
```

`--mode targeted` produces only feedback, even if the tests are green. It also inspects untracked files and local changes. If no reliable module is identified, it executes all reported suites. In a real build, extend the selection to the affected dependents (e.g. api → integration); fallback remains all suites when the impact is uncertain. `--mode validate` requires a committed candidate and a clean worktree, controls the full diff, executes the complete sequels after `clean`, checks the test reports, SHA and final cleanliness. It refuses protected paths, binary, symlinks and submodule changes by default; any exception is a human decision in a separate and approved validation policy, never a bypass argument given to the writer.
`--sbt2` uses `testFull` instead of `test` for an exhaustive re-execution in sbt 2.x. The script is an example of harness to be adapted and tested; the exact spec scope and exceptions must be checked by a human or an independently approved pathallowlist. It does not cover all Scala buildings, submodules, non-JUnit tests, or ignored files alone. The CI must run in an isolated and clean checkout, with the confidence policy (section 15A). Do not confuse JSON relationship and inviolable attestation.

Wrapper `scripts/ai-test-changed` (executable, shared by Aider, Codex and Claude):

```bash
#!/usr/bin/env bash
set -euo pipefail
: "${AI_BASE_SHA:?Set the approved base commit SHA first}"
repoRoot=$(git rev-parse --show-toplevel)
receiptDir=$(mktemp -d)
printf 'Local feedback receipt: %s\n' "$receiptDir/validation.json"
exec python3 "$repoRoot/scripts/ai-validate.py" --base "$AI_BASE_SHA" \
  --mode targeted --receipt "$receiptDir/validation.json" "$@"
```

At startup, fix `AI_BASE_SHA` the approved revision (not `HEAD` re-evaluated after each commit). For example, in the taskworktree:

```bash
export AI_BASE_SHA="$(git rev-parse origin/main)"
aider --test-cmd "./scripts/ai-test-changed"
```

Before pushing the PR, on a clean and committed candidate:

```bash
receiptDir=$(mktemp -d)
python3 scripts/ai-validate.py --base "$AI_BASE_SHA" --mode validate \
  --receipt "$receiptDir/validation.json"
```

Keeps the evidence structured in the review package (base, merge base, SHA candidate, commands, return codes, number of tests performed and status). If validation is missing, fails or is related to another SHA, does not declare "done". Validation scripts themselves require testing: output sbt non-zero without `[error]`, untracked, commit already created, renamed file to a forbidden path, report absent/empty, SHA changed. Runs these cases on a temporary repo and a sbt This was followed by a mock-up before promoting the policy. Git temporary and temporary sbt simulated; this validates script logic, not commands sbt The end-to-end checks are still to be carried out in CI.
