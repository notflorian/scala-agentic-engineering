# 13. Materiale minimo per la revisione e per ridurre gli scambi

Prima di richiedere una recensione da Codex, Claude o un collega, prepara sempre un breve pacchetto:

```text
Ticket/spec :
Objectif :
Non-objectifs :
Fichiers modifiés :
Base SHA / merge base / PR head SHA :
Diff base → candidat + fichiers non suivis :
Exigences → preuves (commandes, résultats, rapports et SHA) :
Tests exécutés :
Tests non exécutés et pourquoi :
Risques résiduels :
Questions ouvertes :
```

Una revisione senza spec produce commenti generici; una revisione con obiettivi, limiti e test produce più spesso rendimenti attuabili. Prima di tutto, fornire il contratto e diff senza le conclusioni dello scrittore; le giustificazioni vengono dopo la prima analisi indipendente. Il pacchetto deve essere rigenerato quando lo SHA cambia.

Per le PR, in particolare monitor:

```text
- nombre de fichiers modifiés ;
- taille du diff ;
- fichiers hors scope ;
- CI rouge ;
- tests ajoutés qui ne peuvent pas échouer ;
- refactor non demandé ;
- changement implicite de contrat public ou JSON ;
```
