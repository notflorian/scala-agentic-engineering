# 1. Principio guida

Per uno sviluppatore Scala senior, l’obiettivo principale è massimizzare il rapporto seguente. Scrivere codice più in fretta è secondario.

```text
Modifiche utili, distribuite in produzione e stabili
÷
(diff inutili + osservazioni emerse in revisione + bug + crediti consumati + tempo umano)
```

Il buon modello mentale:

```text
Tu = responsabile tecnico con l’ultima parola
IntelliJ = riferimento per la struttura Scala/JVM e centro di controllo
JetBrains AI = assistenza in linea e azioni a basso attrito nell’IDE
Codex = agente esecutivo principale per le issue ordinarie + revisore indipendente quando scrive Claude
Claude Code = agente principale per ragionamento, debug e architettura + revisore indipendente quando scrive Codex
Qwen locale = assistente economico
GitHub Copilot = integrazione nativa GitHub per issue, PR e revisione automatica
Aider = diff piccoli e chiari, orientati a Git
MCP + Sourcebot + Context7 = contesto mirato
RTK + Headroom = riduzione del rumore
Jev = livello decisionale probabilistico per classificare, assegnare punteggi e instradare; mai come modello di programmazione né come unico controllo critico
GPT‑6 Luna / GPT‑6.2 Sol / GPT‑6.2 Astra = opzioni Codex per cicli brevi, lavoro agentico e compiti di frontiera
Haiku 5.5 / Sonnet 5.5 / Opus 5.5 / Fable 5.2 = opzioni Claude secondo volume, controllo umano e autonomia
Test + Stryker4s + CI = verifiche finali deterministiche
```
