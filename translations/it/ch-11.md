# 11. Quando usare Aider e dove collocare OpenCode e Qwen Code

Aider rimane utile, mantenuto e molto efficace per gli spostamenti **coppia terminale di programmazione orientata verso Git**: è dato file accurati, produce patch leggibili, e la storia casuale Git rimane l'undo stack.

OpenCode è un agente open source più generalista, con terminale, IDE/desktop a seconda della configurazione, sessioni multiple e LSP/integrazionesMCP. Scala, è interessante, ma devi rimanere preciso: alcune funzionalità LSP sono ancora documentate come sperimentali o dipendenti da una bandiera di configurazione e **Metals non fa parte dei LSP via cavo nativamente impegnati** — la domanda di integrazione aperta sul deposito temporaneo OpenCode (January aggiunto) 2026) è ancora alla fase di discussione a metà luglio 2026. Pertanto, non basa una decisione di architettura del team solo su OpenCode Test sul tuo repo, con conseguente Metals, quindi misura la qualità dei diffs.

## Quando usare Aider

Usalo per:

* piccola patch mirata;
* correzione di un test;
* rinominazione locale;
* semplice migrazione meccanica;
* cambiamento dove il diff Git è centrale;
* loop lint/test molto breve.

Non usarlo per:

* architettura;
* grande eredità;
* bug multi-module;
* profondo commercio refactor;
* progettazione decisione.

Aider È tutto il meglio se rispetti questa regola: **aggiungi alcuni file, fai una richiesta specifica, controlla il diff, esegui test mirati[**. Se aggiungi troppi file, ricrea il problema che volevi evitare: contesto costoso, attenzione diluita, più ampio diff.

Se questa disciplina vi conta meno del feedback LSP, OpenCode/Qwen Code può meglio coprire gli stessi casi, ma solo dopo la convalida locale sul vostro repo Scala.

## Esempio: il comando di prova che qualsiasi imbracatura deve ricevere

La leva numero uno del lint/test loop è un comando comune, riproducibile e veloce. `FooSpec` dal nome di casualità `Foo.scala`: la suite può portare un altro nome e un altro `testOnly` senza un test selezionato può avere successo. CI, `git diff HEAD` non vede i commit della PR. Quindi fissare un vuoto **baseGit immutabilizzazione** e confrontarla con il candidato (basemer), tenendo conto di tutti gli stati aggiuntivi Git per il feedback locale.

Esempio `scripts/ai-validate.py` (Python 3, Git, sbt; adatta `MODULES`, path policy e report JUnit al progetto). Le suite elencate devono coprire tutti i moduli di prova, compresi i moduli di integrazione; una suite non-test run richiede una configurazione esplicita, non un successo silenzioso.

```python
#!/usr/bin/env python3
"""Repository-specific example: adapt and protect the module map and policy."""
import argparse
import json
import re
import subprocess
import sys
import xml.etree.ElementTree as ET
from pathlib import Path

MODULES = {"api/": "api", "integration/": "integration"}
PROTECTED_NAMES = {"build.sbt", "plugins.sbt", "AGENTS.md", "CLAUDE.md", "CODEOWNERS", ".gitmodules"}
PROTECTED_DIRS = {".github", ".claude", ".codex", ".agents", "project", "migrations", "scripts"}
MAX_FILES, MAX_LINES = 20, 600


def git(*args):
    return subprocess.check_output(["git", *args])


def nul_paths(*args):
    return {p.decode("utf-8", "surrogateescape") for p in git(*args).split(b"\0") if p}


def changed_paths(base):
    # Union of committed, staged, unstaged and untracked paths; count renames as delete/add.
    return (nul_paths("diff", "--name-only", "-z", "--no-renames", base, "HEAD")
            | nul_paths("diff", "--cached", "--name-only", "-z", "--no-renames", base)
            | nul_paths("diff", "--name-only", "-z", "--no-renames", base)
            | nul_paths("ls-files", "--others", "--exclude-standard", "-z"))


def protected(path):
    parts = Path(path).parts
    return (bool(set(parts) & PROTECTED_DIRS) or Path(path).name in PROTECTED_NAMES
            or path.endswith(".sbt"))


def check_diff(base, head):
    # A final proof requires a committed candidate; never ignore untracked files.
    if git("status", "--porcelain=v1", "-z", "--untracked-files=all"):
        raise ValueError("Dirty candidate (including untracked files); inspect and commit authorized files first")
    raw = git("diff", "--raw", "-z", "--no-renames", base, head).split(b"\0")
    for metadata, raw_path in zip(raw[0:-1:2], raw[1:-1:2]):
        old_mode, new_mode = metadata[1:].split(b" ", 2)[:2]
        if {old_mode, new_mode} & {b"120000", b"160000"}:
            raise ValueError(f"Symlink or submodule requires separate review: {raw_path!r}")
    records = git("diff", "--numstat", "-z", "--no-renames", base, head).split(b"\0")
    count, lines = 0, 0
    for record in filter(None, records):
        added, removed, raw_path = record.split(b"\t", 2)
        path = raw_path.decode("utf-8", "surrogateescape")
        if protected(path):
            raise ValueError(f"Protected path requires separate human-approved policy: {path!r}")
        if added == b"-" or removed == b"-":
            raise ValueError(f"Binary change requires separate review: {path!r}")
        count += 1
        lines += int(added) + int(removed)
    if count > MAX_FILES or lines > MAX_LINES:
        raise ValueError(f"Diff exceeds policy: {count} files, {lines} lines")
    return {"files": count, "lines": lines}


def select_modules(paths):
    # Unknown/shared changes or no identified tests -> all declared test modules.
    if not paths or any(not any(p.startswith(prefix) for prefix in MODULES) for p in paths):
        return list(MODULES.values())
    return [module for prefix, module in MODULES.items()
            if any(path.startswith(prefix) for path in paths)]


def run_step(args, results):
    rc = subprocess.run(args, check=False).returncode
    results.append({"argv": args, "exit_code": rc})
    if rc:
        raise ValueError(f"Command failed ({rc}): {args!r}")


def verify_reports(prefix):
    # Adapt to actual report paths and frameworks; after clean, no stale reports.
    executed = 0
    for report in Path(prefix).glob("target/**/TEST-*.xml"):
        suite = ET.parse(report).getroot()
        if suite.tag != "testsuite":
            raise ValueError(f"Unexpected report format: {report}")
        if int(suite.get("failures", "0")) or int(suite.get("errors", "0")):
            raise ValueError(f"Failed tests in report: {report}")
        executed += int(suite.attrib["tests"]) - int(suite.get("skipped", "0"))
    if executed <= 0:
        raise ValueError(f"No executed tests proven for {prefix}")
    return executed


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--base", required=True, help="Approved full Git commit SHA")
    parser.add_argument("--mode", choices=["targeted", "validate"], required=True)
    parser.add_argument("--sbt2", action="store_true")
    parser.add_argument("--receipt", type=Path, required=True)
    args = parser.parse_args()
    root = Path(git("rev-parse", "--show-toplevel").decode().strip()).resolve()
    receipt = args.receipt.resolve()
    if receipt == root or root in receipt.parents:
        parser.error("Receipt must be outside the repository")
    import os
    os.chdir(root)
    result = {"base": args.base, "mode": args.mode, "steps": [], "status": "FAILED"}
    try:
        if not re.fullmatch(r"[0-9a-f]{40}|[0-9a-f]{64}", args.base):
            raise ValueError("Expected a full immutable base SHA")
        head = git("rev-parse", "HEAD").decode().strip()
        base = git("merge-base", args.base, head).decode().strip()
        result.update(head=head, merge_base=base)
        if args.mode == "validate":
            result["diff"] = check_diff(base, head)
            modules = list(MODULES.values())
            # Full final validation, not a heuristic selection.
            run_step(["sbt", "scalafmtCheckAll", "compile", "Test/compile"], result["steps"])
        else:
            modules = select_modules(changed_paths(base))
        result["modules"] = modules
        test_task = "testFull" if args.sbt2 else "test"
        for prefix, module in MODULES.items():
            if module not in modules:
                continue
            # Explicit module suite: do not infer test names from source filenames.
            command = ["sbt", f"project {module}"]
            if args.mode == "validate":
                command.append("clean")
            run_step([*command, test_task], result["steps"])
            if args.mode == "validate":
                result.setdefault("executed_tests", {})[module] = verify_reports(prefix)
        if args.mode == "validate":
            if git("rev-parse", "HEAD").decode().strip() != head:
                raise ValueError("Candidate SHA changed during validation")
            check_diff(base, head)
            result["status"] = "PASSED"
        else:
            result["status"] = "FEEDBACK_ONLY"
    except (OSError, ValueError, subprocess.SubprocessError, ET.ParseError, KeyError) as exc:
        result["error"] = str(exc)
    finally:
        receipt.write_text(json.dumps(result, indent=2) + "\n", encoding="utf-8")
    print(json.dumps(result))
    return 0 if result["status"] in {"PASSED", "FEEDBACK_ONLY"} else 1


if __name__ == "__main__":
    sys.exit(main())
```

`--mode targeted` produce solo feedback, anche se i test sono verdi. Ispeziona anche i file non estratti e le modifiche locali. Se non viene identificato un modulo affidabile, esegue tutte le suite segnalate. In una reale costruzione, estendere la selezione ai dipendenti colpiti (ad esempio, api impegnativi). → integrazione); fallback rimane tutte le suite quando l'impatto è incerto. `--mode validate` richiede un candidato impegnato e un worktree pulito, controlla il diff completo, esegue i sequel completi dopo aver verificato `clean`, controlla i rapporti di prova, SHA e pulizia finale. Si rifiuta percorsi protetti, binari, collegamenti simlink e modifiche submoduli per impostazione predefinita; qualsiasi eccezione è una decisione umana in una politica di validazione separata e approvata, mai un argomento di bypass dato allo scrittore.
`--sbt2` Utilizzazione `testFull` invece di dare `test` per una esaustiva riesecuzione in materia sbt 2.x. Lo script è un esempio di imbracatura da adattare e testare; l'esatto campo spec e le eccezioni devono essere controllate da un umano o da un pathallowlist indipendente approvato. Scala edifici, sottomoduli, test non-JUnit, o i file ignorati da soli. CI deve essere eseguito in un checkout isolato e pulito, con la politica di fiducia (sezione limite 15A). Non confusa l'argomento JSON rapporto e inviolabile attestazione.

Wrapper: `scripts/ai-test-changed` (eseguibile, condiviso da interessi Aider, Codex e Claude):

```bash
#!/usr/bin/env bash
set -euo pipefail
: "${AI_BASE_SHA:?Set the approved base commit SHA first}"
repoRoot=$(git rev-parse --show-toplevel)
receiptDir=$(mktemp -d)
printf 'Local feedback receipt: %s\n' "$receiptDir/validation.json"
exec python3 "$repoRoot/scripts/ai-validate.py" --base "$AI_BASE_SHA" \
  --mode targeted --receipt "$receiptDir/validation.json" "$@"
```

All'avvio, fissare obiettivi `AI_BASE_SHA` la revisione approvata (non è necessario `HEAD` rivalutato dopo ogni commit). Ad esempio, nel taskworktree:

```bash
export AI_BASE_SHA="$(git rev-parse origin/main)"
aider --test-cmd "./scripts/ai-test-changed"
```

Prima di spingere la PR, su un candidato pulito e impegnato:

```bash
receiptDir=$(mktemp -d)
python3 scripts/ai-validate.py --base "$AI_BASE_SHA" --mode validate \
  --receipt "$receiptDir/validation.json"
```

Mantiene le prove strutturate nel pacchetto di revisione (base, base di fusione, candidato SHA, comandi, codici di ritorno, numero di test eseguiti e stato). Se la validazione manca, fallisce o è correlata ad un altro SHA, non dichiara "done". sbt non-zero senza indugio `[error]`, non tracciato, commit già creato, rinominato file ad un percorso proibito, report assente/vuoto, SHA cambiato. sbt Questo è stato seguito da un mock-up prima di promuovere la politica. Git temporaneo e temporaneo sbt simulato; questo convalida la logica dello script, non i comandi necessari sbt I controlli finali sono ancora da effettuare in caso di CI.
