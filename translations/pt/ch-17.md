# 17. Fluxo de trabalho final

Para uma verdadeira tarefa profissional Scala :

```text
1. Humano: especificação, requisitos → evidências, riscos, itens fora do escopo e modo de supervisão. WIP ≤ 2 histórias independentes no início
2. Sourcebot + ScalaSemantic + IntelliJ/Metals: contexto relevante. Codebase-Memory em projetos poliglotas
3. Worker econômico para extração verificável. Mesmo modelo do agente principal para decisões complexas
4. Implementador: GPT‑6.2 Sol Medium ou Opus 5.5 Medium. High / Astra / Fable somente quando justificado
5. Implementador: plano antes de editar, worktree e permissões específicos da tarefa
6. Humano: aprovação do plano. Em código crítico, outro agente prepara os testes e uma pessoa valida o oráculo
7. Implementador: diff pequeno e testes direcionados. Reprodução que falha antes da correção do bug
8. IntelliJ / scripts: compilação, formatação, suítes realmente executadas e evidências estruturadas
9. Implementador: autorrevisão do diff completo
10. Outra família: revisão independente somente leitura no SHA exato, com achados fundamentados
11. Humano: triagem dos achados
12. Implementador ou responsável explicitamente designado: correções direcionadas, sem escrita concorrente
13. CI independente: verificações e evidências no candidato final
14. Codex Goal / Heartbeat / Cloud ou Claude /steward / Cloud Auto-fix: acompanhamento delimitado se útil, com revalidação a cada push
15. Luna/Qwen: resumo da PR. Humano: merge após validar o SHA final e os gates de integração
16. Pipeline dedicado: artefato imutável, staging, lançamento aprovado, canary e rollback conforme o risco
17. Runtime: verificar SLO e invariantes. Declarar estabilidade após a janela de observação
```

O resumo mais importante:

```text
Plano sólido.
Diff pequeno.
Evidências determinísticas no SHA correto.
Revisão independente proporcional ao risco.
Validação humana e permissões isoladas.
Implantação controlada, observabilidade e rollback.
Modelo caro somente quando um erro custaria caro.
```
